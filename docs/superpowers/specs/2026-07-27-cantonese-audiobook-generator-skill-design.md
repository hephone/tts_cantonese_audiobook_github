# Cantonese Audiobook Generator Skill 设计

## 目标

在本项目中建立一个可重复使用的 Codex 项目级技能，将普通话非虚构电子书处理为自然的香港粤语讲书稿，并使用项目已经安装的 Microsoft `edge-tts` 雲龍男声生成适合长时间收听的 MP3。

技能适用于知识类、社会学、商业、思考类和其他非虚构作品。它不把普通话逐字替换成粤语，而是以香港知识节目和专业讲书主播的表达方式重写，同时忠实保留原作者的观点、数据、案例、逻辑和立场。

## 技能位置

技能使用项目级目录：

```text
.agents/skills/cantonese-audiobook-generator/
├── SKILL.md
└── evals/
    └── evals.json
```

`SKILL.md` 保存触发条件、完整工作流程、语言要求、音频要求和验收标准。`evals/evals.json` 保存三个轻量测试场景，用于验证分集规划、粤语改写和最终目录结构。

不复制现有 TTS 实现。技能直接使用：

```text
.venv/bin/python
.venv/bin/edge-tts
cantonese_audiobook_tts/generate_all.py
```

这样可以避免项目中出现两套容易产生差异的生成程序。

## 触发范围

当用户提出以下类型的项目任务时使用该技能：

- 把普通话电子书制作成粤语有声读物
- 把书面中文改写为香港粤语讲书稿
- 为知识类书籍规划粤语音频分集
- 检查粤语讲稿的普通话残留或朗读自然度
- 使用雲龍粤语男声批量生成有声书
- 继续、中断恢复或重新生成本项目的粤语音频

单纯翻译一句粤语、生成与书籍无关的短语音、处理普通话或其他语言 TTS 时不触发。

## 默认配置

| 项目 | 默认值 |
| --- | --- |
| TTS 工具 | 项目 `.venv` 中的 `edge-tts` |
| 语言 | `zh-HK` |
| 声音 | `zh-HK-WanLungNeural` |
| 语速 | `+20%`，约 1.2 倍 |
| 音频格式 | MP3 |
| 单集目标 | 20–40 分钟，推荐约 30 分钟 |
| 讲稿风格 | 70% 粤语口语，30% 书面表达 |

声音风格应平静、专业、有思考感，接近香港知识节目，避免新闻播报、客服机器人和短视频配音感。

## 工作流程

### 1. 分析书籍结构

读取电子书或用户指定的源文件，识别标题、章节、小节和内容边界。不要立即转换全文。

先输出分集规划，包含：

- 集数
- 标题
- 内容范围
- 预计时长

按照听书体验重新组织分集。每集目标为 20–40 分钟，平均约 30 分钟。优先在完整论点、案例或小节边界处分集，不机械地按字符数截断。

在用户确认规划后再进入全文改写。若用户明确授权直接执行已有规划，可以继续而不重复询问。

### 2. 改写香港粤语讲书稿

以香港粤语知识类有声书编辑的身份改写内容。

改写目标不是逐字翻译，而是让香港粤语主播自然讲述同一内容。语言比例约为 70% 粤语口语和 30% 书面表达。

必须保留：

- 原作者观点和立场
- 数据及其限定条件
- 案例和人物关系
- 推理顺序和因果逻辑
- 必要的专业术语

不得增加新观点、删除实质内容、改变作者立场或把不确定内容说成确定事实。

为朗读优化句子：

- 拆分过长句子
- 减少复杂从句
- 使用适合口头表达的语序
- 使用 `/` 表示轻微停顿
- 控制语气词数量

避免网络聊天和过度年轻化表达，不滥用“喎、啦、啫、咯”。

### 3. 粤语质量检查

检查普通话词汇残留、粤语语法、香港表达习惯和朗读自然度。

重点检查但不机械替换：

- 因此
- 通过
- 进行
- 认为
- 此外
- 其中
- 以及

这些词在特定书面语境中可能合理。只有影响香港粤语自然度时才修改。

质量检查只输出需要修改的内容：

```text
原句：

修改：

原因：
```

如果没有问题，输出：

```text
无需修改
```

完成修改后再次检查，直到没有未处理的问题。

### 4. TTS 准备

在不改变内容的前提下调整：

- 标点
- 停顿
- 分段
- 数字、缩写和符号的可朗读形式

检查每个讲稿的预计时长。过长时在自然内容边界拆分；过短时只合并相邻且逻辑连续的内容。

### 5. 试听确认

正式批量生成前，先从代表性内容生成约一分钟试听。试听必须使用与正式版相同的声音和语速。

向用户提供试听音频、声音名称、语速和实际时长。用户确认后才批量生成。用户已经明确确认过同一项目配置时，可以复用确认结果。

### 6. 批量生成

使用项目环境执行 TTS：

```sh
.venv/bin/python -m edge_tts \
  --voice zh-HK-WanLungNeural \
  --rate=+20% \
  --file INPUT \
  --write-media OUTPUT
```

对于当前固定目录的批量任务，优先运行：

```sh
./generate_cantonese_audiobook.sh
```

生成规则：

- 输出 MP3
- 文件名使用 `001-章节标题.mp3` 格式
- 保持目录顺序
- 已存在且非空的 MP3 默认跳过
- 失败时保留已完成文件，允许重新运行后继续
- 不把密码、密钥、Cookie 或令牌写入命令、日志、代码或文档

## 音频参数处理

不要混淆采样率和码率。`48 kbps` 不等于 `48 kHz`。

生成后使用 `ffprobe` 检查实际格式、时长、采样率和文件大小。默认保留 Microsoft 输出的原始 MP3，避免无必要的重复编码。

只有用户明确需要 48 kHz，或目标播放器、发行平台有硬性要求时，才使用 `ffmpeg` 转换为 48 kHz。转换后再次使用 `ffprobe` 验证。

## 最终输出结构

通用任务输出：

```text
Book/
├── README.md
├── Script/
│   ├── 001.md
│   └── 002.md
└── Audio/
    ├── 001-章节标题.mp3
    └── 002-章节标题.mp3
```

`README.md` 记录：

- 书名和源文件
- 分集清单
- 声音与语速
- 音频时长
- 生成日期
- 任何读音或文本处理说明

当前项目已有明确输出目录时，允许沿用已有结构，但必须在 `README.md` 中记录映射关系。

## 错误处理

- 找不到电子书或源文件时，报告准确路径并停止转换。
- 无法识别章节时，先给出可解释的人工分段建议。
- `.venv` 或 `edge-tts` 不存在时，提示根据 `requirements-tts.txt` 重建环境，不自动安装到临时目录。
- 网络生成失败时，重试有限次数，并保留已完成音频。
- 声音不可用时，不静默换声；列出可用的同等级香港粤语 Neural Voice，得到用户确认后再继续。
- 音频不在 20–40 分钟目标范围时，先判断是否有自然的拆分或合并边界，不为追求精确时长破坏内容结构。

## 验收标准

技能完成一次任务时应满足：

1. 在全文改写前提供可审阅的分集规划。
2. 粤语讲稿保留原文观点、数据、案例和逻辑。
3. 质量检查采用指定的“原句／修改／原因”格式。
4. 正式生成前提供约一分钟试听，除非同一配置已经确认。
5. 正式音频使用雲龍男声和 1.2 倍语速。
6. 每个 MP3 对应一个讲书章节，目标为 20–40 分钟。
7. 使用 `ffprobe` 验证生成结果。
8. 最终目录、文件名和 README 可让用户按顺序播放并追溯来源。

## 测试范围

技能创建后增加三个轻量测试：

1. 输入一份带有三级标题的非虚构章节，检查是否先输出合理的 20–40 分钟分集规划。
2. 输入一段带有普通话书面表达的知识类文本，检查是否改写为自然香港粤语，同时保留事实和逻辑。
3. 输入一个已经确认分集和声音的任务，检查是否输出正确目录、命名规则和 TTS 命令，并跳过重复确认。

测试不生成整本书或长音频，以控制时间与外部调用成本。
